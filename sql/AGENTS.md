# sql/AGENTS.md

## 适用范围

本文件适用于 SQL 会话、后端会话中的数据库变更任务，以及任何修改 `sql/` 的任务。

不要在本文件中编写实际业务表结构。实际 SQL 脚本应放在 `sql/schema.sql`、`sql/data.sql` 或 `sql/migrations/` 中。

## 数据库来源

- MySQL 8 是唯一目标数据库。
- `sql/schema.sql` 是数据库结构唯一来源。
- 数据库设计文档必须与 `sql/schema.sql` 保持一致。
- 已执行或已合并的迁移脚本不要直接修改，应新增迁移脚本。

## 字段规范

- 金额字段统一使用 `decimal(10,2)`，如确有更高精度需求，必须先说明原因。
- Java 中对应金额字段必须使用 `BigDecimal`。
- 状态字段统一使用 `varchar(32)`。
- 时间字段优先使用 `datetime`。
- 每张业务表必须包含 `create_time` 和 `update_time`。
- 需要软删除时，统一说明字段名、默认值和查询过滤策略。

## 数据库变更同步规则

新增、删除、重命名或修改字段时，必须同步更新：

1. `sql/schema.sql` 或 `sql/migrations/`；
2. 数据库设计文档；
3. 后端 `entity`；
4. MyBatis-Plus `mapper`；
5. 相关 `dto`、`vo`；
6. 测试数据；
7. 相关 API 文档和测试用例。

禁止只改 Java 实体不改 SQL，也禁止只改 SQL 不改后端代码。

## 状态字段规则

- 拼单状态、付款状态、取餐状态必须与后端枚举保持一致。
- 状态字段不存中文文案，只存稳定英文枚举值。
- 状态展示文案由前端或后端 VO 转换，不直接依赖数据库中文值。

## 索引设计原则

- 高频查询条件应建立索引。
- 外键关联字段和业务关联字段应评估索引。
- 唯一业务约束优先用唯一索引表达。
- 不为低选择性字段盲目建索引。
- 不为尚未出现的复杂查询提前堆索引。
- 新增索引必须说明服务的查询场景。

## 数据安全与可维护性

- 字段删除和类型收窄必须说明历史数据影响。
- 涉及默认值、非空约束、唯一约束时必须说明业务原因。
- 初始化数据放在 `sql/data.sql`。
- 迁移脚本文件名应包含时间或版本号，便于排序和审查。
