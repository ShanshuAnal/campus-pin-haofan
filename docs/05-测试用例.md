# 校园拼好饭系统 V2 测试用例

## 1. 文档目标

本文定义校园拼好饭系统 V2 的测试范围、回归基线、核心场景和验收标准。

V2 测试需要覆盖当前 MVP 已完成能力，并新增取消拼单、超时关闭、履约事件、并发控制、Redis 增强、RocketMQ 异步能力和前端产品化改版验证。

## 2. 当前回归基线

后端集成测试已通过记录：

```text
81 tests, 0 failures
```

V2 开发前必须保留以下 MVP 主流程可用：

```text
登录
-> 发起拼单
-> 成员加入
-> 凑单计算
-> 锁定拼单
-> 优惠分摊
-> 标记付款
-> 指定取餐人
-> 更新取餐状态
-> 完成拼单
```

V2 不允许破坏已有认证、拼单、付款、取餐和我的拼单接口。

## 14. 验收标准

V2 必做能力验收：

- 取消拼单有明确权限、状态校验和事件记录；
- 超时关闭引入 `EXPIRED`，且和 `CANCELLED` 语义清楚；
- 延迟和异常通过事件记录，不扩散主状态；
- 并发冲突以 MySQL 事务和状态校验保证正确；
- 拼单大厅和详情页从后台表格改为校园拼单产品体验；
- API、数据库、领域和测试文档保持一致；
- MVP 主流程回归通过。

V2 可选增强验收：

- Redis 防重复提交、短时锁和缓存不改变核心状态来源；
- RocketMQ 消息消费幂等，失败不破坏主流程；
- 统计和通知失败不影响拼单完成。
