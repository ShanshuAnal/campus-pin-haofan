# 校园拼好饭系统 V2 测试用例

## 1. 文档目标

本文定义校园拼好饭系统 V2 的测试范围、回归基线、核心场景和验收标准。

V2 测试需要覆盖当前 MVP 已完成能力，并新增取消拼单、超时关闭、履约事件、并发控制、Redis 增强、RocketMQ 异步能力和前端产品化改版验证。

## 2. 当前回归基线

后端集成测试已通过记录：

```text
52 tests, 0 failures
```

V2 开发前必须保留以下 MVP 主流程可用：

```text
登录
-> 发起拼单
-> 成员加入
-> 凑单计算
-> 锁定拼单
-> 优惠分摊
-> 标记付款
-> 指定取餐人
-> 更新取餐状态
-> 完成拼单
```

V2 不允许破坏已有认证、拼单、付款、取餐和我的拼单接口。

| 范围 | 测试重点 | 优先级 |
| --- | --- | --- |
| 认证回归 | 登录、刷新、登出、Redis 黑名单 | MVP 回归 |
| 拼单主流程 | 创建、加入、锁定、付款、取餐、完成 | MVP 回归 |

## 9. 并发控制测试

V2 并发控制必须以 MySQL 事务、状态校验、唯一约束和版本字段为主。

| 用例 ID | 场景 | 并发操作 | 预期 |
| --- | --- | --- | --- |
| CONC-001 | 重复加入 | 同一用户并发加入同一拼单 | 只有一条参与记录成功 |
| CONC-002 | 加入与锁定冲突 | 成员加入，发起人锁定 | 以事务提交顺序为准，失败方返回 `409` |
| CONC-003 | 取消与加入冲突 | 发起人取消，成员加入 | 只有一个操作成功 |
| CONC-004 | 超时与锁定冲突 | 超时关闭，发起人锁定 | 只有一个状态更新成功 |
| CONC-005 | 超时与取消冲突 | 系统过期，发起人取消 | 只进入 `EXPIRED` 或 `CANCELLED` 之一 |
| CONC-006 | 重复付款 | 成员重复提交付款标记 | 幂等或返回 `409`，不重复累计金额 |
| CONC-007 | 取餐状态重复推进 | 两个请求推进同一状态 | 只成功一次 |

## 14. 验收标准

V2 必做能力验收：

- 取消拼单有明确权限、状态校验和事件记录；
- 超时关闭引入 `EXPIRED`，且和 `CANCELLED` 语义清楚；
- 延迟和异常通过事件记录，不扩散主状态；
- 并发冲突以 MySQL 事务和状态校验保证正确；
- 拼单大厅和详情页从后台表格改为校园拼单产品体验；
- API、数据库、领域和测试文档保持一致；
- MVP 主流程回归通过。

V2 可选增强验收：

- Redis 防重复提交、短时锁和缓存不改变核心状态来源；
- RocketMQ 消息消费幂等，失败不破坏主流程；
- 统计和通知失败不影响拼单完成。
