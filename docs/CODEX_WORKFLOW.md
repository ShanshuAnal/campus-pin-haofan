# Codex 多会话开发流程

## 目标

本文件定义校园拼好饭系统的多会话并行开发流程，避免不同 Codex 会话互相覆盖代码、接口或数据库设计。

## 会话类型

### 主控会话

职责：

- 需求澄清；
- 任务拆分；
- 接口契约协调；
- 数据库设计协调；
- 任务看板维护；
- 跨会话冲突处理。

允许修改：

- `AGENTS.md`
- `README.md`
- `docs/`
- `sql/`

### 后端会话

职责：

- 后端工程和业务接口；
- 业务规则；
- 金额计算；
- 状态流转；
- 后端测试。

允许修改：

- `backend/`
- 后端相关 `docs/`
- 后端相关 `sql/`

除非用户明确要求，不修改 `frontend/`。

### 前端会话

职责：

- 前端页面；
- API 调用封装；
- 前端状态管理；
- 前端交互和展示。

允许修改：

- `frontend/`
- 前端相关 `docs/`

除非用户明确要求，不修改 `backend/`、`sql/schema.sql` 或迁移脚本。

### 测试会话

职责：

- 测试用例；
- 接口验证；
- Bug 复现；
- 回归检查；
- 质量审查。

允许修改：

- 测试代码；
- 测试文档；
- 任务相关说明。

不主动修改核心业务代码，除非任务明确要求。

### 文档汇报会话

职责：

- README；
- LLM 辅助开发记录；
- 演示脚本；
- PPT 材料；
- 开发计划和总结。

允许修改：

- `docs/`
- `README.md`

不修改业务代码、工程脚手架或 SQL 表结构。

## 任务启动流程

每个会话开始前必须：

1. 阅读根目录 `AGENTS.md`。
2. 阅读当前领域的 `AGENTS.md`。
3. 阅读 `docs/TASK_BOARD.md`。
4. 阅读当前任务相关文档。
5. 检查 Git 状态。
6. 确认允许修改范围。

任务看板不存在时，先创建模板，不直接开始 coding。

## 任务看板流程

- 开始任务前，将任务状态标为 `DOING`。
- 任务无法继续时，将状态标为 `BLOCKED` 并说明原因。
- 任务完成并验证后，将状态标为 `DONE`。
- 不删除历史任务。
- 不提前填充大量虚构任务。

## Git 分支建议

推荐分支：

- `main`：稳定可演示版本。
- `dev`：日常集成分支。
- `codex/docs-*`：文档任务。
- `codex/backend-*`：后端任务。
- `codex/frontend-*`：前端任务。
- `codex/test-*`：测试任务。
- `codex/sql-*`：数据库任务。
- `codex/redis-*`：Redis 增强任务。
- `codex/mq-*`：RocketMQ 增强任务。

规则：

- 每个会话原则上只在自己的任务分支上工作。
- 分支名建议包含任务 ID 或任务主题。
- 不在 `main` 上直接开发。
- 不提交与当前任务无关的文件。
- 发现其他会话改动时，不要擅自回滚。

提交信息建议：

```text
feat(order): implement join group order
fix(payment): fix discount allocation rounding
docs(api): update order API contract
test(order): add status transition cases
```

## 接口和数据库冲突处理

发现以下情况时必须暂停并报告：

- API 文档与后端实现不一致；
- API 文档与前端 mock 或类型定义不一致；
- 数据库设计文档与 `sql/schema.sql` 不一致；
- Java 实体与数据库字段不一致；
- 状态枚举在前端、后端、数据库中不一致；
- 金额字段类型不符合规则；
- 同一文件存在其他会话未说明的改动。

报告时说明：

- 冲突文件；
- 冲突内容；
- 当前任务受影响点；
- 建议处理方案。

## 任务交接格式

每个会话结束时输出：

```text
本次完成：
修改/新增文件：
运行命令：
验证方式：
未完成事项：
接口影响：
数据库影响：
对其他会话的影响：
下一步建议：
```

未执行命令或验证时，必须说明原因。
