# 校园拼好饭 V2 演示脚本

## 1. 演示准备

- 后端服务：启动 Spring Boot，确认 `http://localhost:8080/api` 可访问。
- 前端服务：在 `frontend/` 执行 `npm run dev -- --host 0.0.0.0 --port 5173`，使用 `http://localhost:5173`。
- 演示账号：准备发起人账号 A 和参与者账号 B；如环境为空，可现场注册。
- 演示定位：系统用于校园内部拼单协同，不接真实外卖商家，不接真实支付。

## 2. 主流程演示

1. 注册/登录账号 A，进入拼单大厅。
2. 展示大厅首页：顶部搜索、概览卡片、拼单卡片流、状态/类型筛选。
3. 点击“发起拼单”，创建一个奶茶或食堂拼单，设置人数、满减门槛、截止时间和取餐点。
4. 返回大厅，搜索刚创建的拼单，展示人数进度、满减进度、倒计时和取餐点。
5. 进入详情页，展示流程步骤：发起、加入、锁单、付款、取餐、完成。
6. 切换账号 B 登录，进入同一拼单详情，填写餐品名称、数量、单价和备注，提交加入。
7. 切回账号 A，刷新详情，查看成员金额、餐品明细和满减差额。
8. 发起人点击锁单，展示实际优惠、优惠分摊、应付金额、应付总额。
9. 参与者账号 B 标记自己付款。
10. 发起人账号 A 确认成员付款。
11. 发起人指定取餐人。
12. 取餐人依次推进取餐状态，直到完成拼单。
13. 展示“我的拼单”中我发起、我参与、待付款、历史拼单。
14. 展示“数据看板”中今日拼单数、成功拼单数、累计节省金额、热门类型和热门店铺。

## 3. V2 异常流程演示

1. 新建一个 `CREATED` 状态拼单，发起人打开详情页并点击取消。
2. 输入取消原因，提交后展示 `CANCELLED` 终态、取消原因和取消时间。
3. 回到大厅，确认取消拼单卡片展示终态样式且不显示加入按钮。
4. 准备一个已过截止时间并被系统关闭的拼单，展示 `EXPIRED` 终态提示。
5. 在详情页确认 `CANCELLED`、`EXPIRED`、`FINISHED` 均不可继续加入、锁单、付款或推进取餐。
6. 在履约过程中记录延迟或异常事件，展示事件时间线。

## 5. 演示注意事项

- 付款是协同标记，不是真实支付。
- 商家和菜品信息来自用户输入或系统记录，不接入外卖平台。
- 终态拼单只允许查看，不允许继续加入、锁单、付款或取餐推进。
- 如果演示环境已有脏数据，优先通过搜索关键词定位本次新建拼单。
